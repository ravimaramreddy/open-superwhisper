Connections use existing Studio services. Local models load when needed and unload after inactivity. Advanced rewriting uses E4B; local fallback provides basic English cleanup.

Keep

  • Microphone selection and permissions
  • Global shortcut and clear recording state
  • Cancel without late or duplicate insertion
  • Local history with Copy original
  • Optional cleanup and deliberate Rewrite action

Remove from the running app

  • API-key forms and provider/model catalogs
  • Accounts, subscriptions, teams and cloud sync
  • Meeting capture and calendar background work
  • Note editor, chat agents and semantic search
  • Unneeded model downloads and packaged engines

Build approach

A focused desktop entrypoint owns recording sessions, fixed-profile inference, history and delivery. The renderer cannot choose arbitrary endpoints, prompts or models. An on-demand local worker uses the exact tested Air models. An app-owned SSH tunnel reaches the existing Studio text service without exposing another server.

Reliability before convenience. Save the original before insertion. Associate each result with its recording and target. Cancel retired requests; never automatically retry an uncertain paste. Empty recordings produce no text. If cleanup fails, retain the raw transcript and show what happened.

Verification

  • Run real audio through Studio and Air, then verify automatic fallback.
  • Check cancellation, silence, target changes, duplicate completion and raw recovery.
  • Build and inspect the packaged Mac app; verify inactive services and discarded dependencies are absent.
  • Run tests, lint, type checks and independent review, then open a PR in the fork.

App data uses a new OpenSuperwhisper directory. Existing OpenWhispr data and Studio services stay intact. OS microphone/accessibility permission requests remain visible. The plan records implementation choices; no approval pause is required.

Design source: OpenWhispr’s existing parchment surfaces, system type, blue accent and compact Mac controls. This sketch describes the simplified structure; verification will use the actual app.
